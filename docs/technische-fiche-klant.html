WinProx — Technische fiche

Facility-meldingen: QR → taken → afhandeling · SaaS voor operationele teams

winprox.app
Versie meeting · juli 2026

Kort overzicht voor IT / security. WinProx is een multi-tenant webapplicatie (Laravel + MySQL) waarop elke klantorganisatie haar eigen afgeschermde omgeving heeft.

Hosting

  • Productie op Linux (EU), bij Cloud86 (gedeelde hosting / Plesk).
  • Toegang via HTTPS (TLS).
  • Stack: PHP 8.2+, Laravel 12, Livewire, MySQL, Vite-frontend.
  • E-mail via SMTP in de EU; betalingen optioneel via Stripe.

GDPR / AVG

  • Klant = verwerkingsverantwoordelijke; WinProx = verwerker.
  • Kader: EU-AVG + Belgische wet (30 juli 2018).
  • Verwerkersovereenkomst (DPA) en subverwerkerslijst beschikbaar.
  • Data-export (account), self-service organisatieverwijdering, bewaartermijnen vastgelegd.
  • Gegevens blijven in de EU (hosting/e-mail); Stripe EU/US indien betalend.

Backups

  • Infrastructuurbackups via de hostingprovider (Cloud86).
  • Bij volledige organisatieverwijdering: technische SQL-snapshot zonder media, max. 30 dagen.
  • Herstelafspraken en RPO/RTO: in overleg / contractueel vast te leggen.

Beschikbaarheid

  • 24/7 bereikbaar als SaaS (browser + QR-portalen).
  • Gepland onderhoud: bij voorkeur buiten kantooruren, met aankondiging waar mogelijk.
  • Formele uptime-SLA: op vraag contractueel af te spreken.

Database

  • MySQL, relationeel model per tenant.
  • Strikte tenant-isolatie: elke query/API-call blijft binnen de eigen organisatie.
  • Geen gedeelde zichtbaarheid tussen klanten.

Authenticatie

  • Beheer: e-mail + wachtwoord (gehashte opslag), sessies.
  • API: Bearer-tokens (Laravel Sanctum), intrekbaar, met scopes.
  • Veldteams: geen login — team-QR + persoonlijk icoon.
  • Melders: publiek QR-portaal zonder account.

Rechten

  • Beheerder: alles (users, bedrijf, abonnement, teams).
  • Medewerker: operationeel (meldingen, taken, locaties) — geen account-/billingbeheer.
  • Worker / teamleader: taken afhandelen via veldportaal; teamleader kan iconen vrijgeven.
  • Autorisatie via policies (least privilege); API-tokens met aparte abilities.

Veiligheid

  • HTTPS, CSRF-bescherming, gehashte wachtwoorden, intrekbaar tokens.
  • Tenant-scoping op alle data-toegang; audit-/activiteitenlogs.
  • Webhooks met HMAC-SHA256-handtekening.
  • API rate limit: 60 req/min per token.
  • Supporttoegang: uitzonderlijk, standaard alleen-lezen.

API

  • REST API v1 (JSON), documentatie in-app + docs.
  • Resources o.a.: meldingen, taken, locaties, units, teams, workers, ESG, vertalingen.
  • Beschikbaar op Corporate (proef op verzoek).
  • IoT-ingest apart via gateway-token (Facility + Corporate).

Webhooks

  • Uitgaande HTTP POST bij events (o.a. issue/task-status, ESG, GPS).
  • Configuratie onder Instellingen → API; secret voor verificatie.
  • Automatische retries bij falen (tot enkele pogingen met oplopende pauze).
  • Zelfde planvereiste als API (Corporate).

AI

  • Optioneel: AI-vertalingen van operationele teksten (meldingen, taken, units, mededelingen, …).
  • Draait op een lokale Ollama-instantie — geen ChatGPT / externe AI-cloud voor deze functie.
  • Teksten blijven binnen jullie verwerkingskader; beheerders kunnen vertalingen corrigeren of de functie uitzetten.
  • Geen generatieve “AI-assistent” die klantprocessen autonoom beslist — vertaling is ondersteuning, geen besluitvorming.
